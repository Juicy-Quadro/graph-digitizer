**最严重的问题**：标定模块混用了两套不兼容的几何模型（投影分解 vs 仿射分解），二者仅在两轴垂直时一致。而项目 README 与代码注释都明确宣称"支持倾斜轴"。**该声明为假**。

**同时被证伪的另一项声明**：README 与"打开图片"对话框都宣传支持 TIFF，但 Chromium 没有 TIFF 解码器——选 TIFF 会静默失败且不弹任何提示。

## P0 · 数据正确性（静默错误数值）

### P0-1 标定用投影分解，应为仿射分解 —— 倾斜轴下逻辑坐标完全错乱
`src/js/core/calibrate.js:107-111`（`toLogical`） 与 `:130-149`（`lineOfConstantX/Y`）

`toLogical` 用 `u = ((p − Xmin) · ax) / |ax|²`（**垂直投影**），而 `lineOfConstantX` 返回的是**平行于 `ay`** 的直线（**仿射等值线**）。两者只在 `ax · ay = 0` 时一致。

**实测判据**（用 GetData 真值数据，函数图的逻辑 X 必须单调）：

| 样例 | 轴夹角 | 投影：落在轴矩形内 | 投影：X 单调 | 仿射：落在轴矩形内 | 仿射：X 单调 |
|---|---|---|---|---|---|
| sample1 | 89.88° | 45/73 | 72/72 | 45/73 | 72/72 |
| sample2 | 89.70° | 65/72 | 71/71 | 65/72 | 71/71 |
| **sample3** | **122.20°** | 34/109 | **77/108 ✗** | 73/109 | **108/108 ✓** |

sample1/2 轴接近垂直，两模型一致，所以问题一直隐身；sample3 是唯一非垂直的样例，**仿射模型给出完美单调，投影模型断裂**。

**影响**：拍照的图、轻微倾斜的图、3D 旋转投影图（正是 sample3 这类）——逻辑 X 沿曲线非单调，数据顺序错乱。审查代理复现：仅 5.7° 倾斜即产生 **1.71 逻辑单位 = X 轴跨距 10.7%** 的误差；`logicalX` 网格模式下请求 X=2/4/6/8/10 实际得到 2.90/5.12/7.34/9.56/11.78。

**修复**：`toLogical` 改用仿射分解 `p = xmin + s·ax + t·ay`（解 2×2 线性方程组），使它与 `toPixel`、`lineOfConstantX/Y` 及四点契约自洽。

### P0-2 改标定后，已数字化点的逻辑坐标从不重算
`src/js/app.js:382-390`、`:908-930`、`:1137-1161`

点对象本身存了 `px`/`py`，重算所需数据齐备，但从未使用。改标定值、移动标定点、切对数轴、点「使用像素坐标」之后，所有点保留旧的 `x`/`y`。

**运行时证据**：把 `xmin.value` 改成 1000 后，点数组**逐字节未变**（`pointsUnchanged: true`），首点仍是 `x = -4.243`，而正确重算值是 `1278.709`。表格和全部 8 种导出都输出旧数字，界面却显示新标定。

**影响**：这是最隐蔽的错误——UI 看起来刷新成功了。

### P0-3 打开第二张图片时，保留上一张图的标定与数据点
`src/js/app.js:677-717`；`src/js/state.js:232-237`（`reset()` 存在但从未被调用）

只替换了 `store.image`，标定（像素坐标）和所有数据点（像素坐标）原样保留并画在新图上。导出文件名是 B，**内容却是 A 的数据**。

### P0-4 `mask` 的 combined 模式把整张图的深色元素都算成曲线
`src/js/core/mask.js:72-78`

第三个子句 `if (dl < db) hit = true`（到线色的距离小于到背景色的距离就命中）接受了一个巨大的半空间：黑轴线、网格线、文字全都"更接近红线"。

**实测**（200×100 合成图：红线 + 黑轴 + 黑标签 + 灰网格）
- color 模式：160 px（占 0.8%）
- combined 模式：670 px（占 3.4%）——**多出的 510 px 全是黑轴/标签/网格**

**影响**：追踪器会沿着坐标轴和文字跑，数据全错。该模式在 UI 里可选（非默认），但用户一旦切过去就中招。

### P0-5 追踪的"跨越断点"会跳到无关结构上并继续追踪它
`src/js/core/trace.js:92-117`

横向容差是相对**当前点**而非**行进点**测的（`lateral ≤ 3`），且跨点后**不更新朝向**，于是追踪器保持旧方向从新位置继续走。

**复现**：真实曲线在 y=40（x=21..69），一条无关的平行条在 y=42（x=71..129）→ 追踪在 50 个点后静默切换到那条条上继续。

### P0-6 `maxPoints` 截断静默发生，导出数据看起来完整
`src/js/core/trace.js:47,51`

`maxPoints=20` 跑 160px 直线 → 返回 `{ok:true, reason:null}`，只覆盖 82..119 而真实范围是 20..179，**没有任何截断标志**。另外 `maxSteps`（400000）是第二道静默上限。

## P1 · 功能失效

### P1-1 「显示识别掩膜」「掩膜透明度」与原生菜单「Toggle Mask Overlay」完全无效
`src/js/app.js:99-103`（创建 canvas view 时传入了**冻结的 options 对象**）、`:961-968`、`:1032-1037`

控件只写 `store.state.sampling.*`，而画布读的是构造时那个字面量对象的 `opt.showMask` / `opt.maskOpacity`，从未被更新。**运行时证据**：取消勾选后 `store.showMask === false`，画布像素差 **0**。

### P1-2 点击系列标签后，画布仍显示上一个活动系列
`src/js/app.js:410-415`（`renderSeriesTabs` 内）

处理器最后一行 `canvasView.setSeries(s.series, s.activeSeries)` 用的是**渲染时捕获的旧快照** `s`（store 每次变更都替换 state 对象）。store、标签高亮、表格都更新了，**只有画布没跟上**（像素差 0）。

### P1-3 点击/拖拽判定按**图像像素**算，行为随缩放变化
`src/js/ui/canvas.js:405-416`

屏幕上的手势却拿图像空间距离比较。实测：
- zoom 40，拖 40 屏幕像素 → 判为点击
- zoom 0.5，抖 2 屏幕像素 → 判为拖拽 → **点击被丢弃**
- zoom 40，区域工具拖 80 屏幕像素 → 判为点击 → **根本没创建区域**

放大到 40 倍后 `fit()` 会落在 zoom<0.5，**2 像素抖动就会丢掉标定点**。

### P1-4 画布与表格的选中态失同步；删除后画布会高亮**错误的点**
`src/js/ui/canvas.js:36,496-504` + `src/js/ui/table.js:181-186`

画布维护自己的 `selected` 集合，`setSeries` 从不重置；表格清空选中时也不通知画布。

**像素采样证据**：删掉第 0 点后，画布把"选中"色 `[240,180,41]` 画在了**原第 1 点**上，而表格显示 `selectedRows: []`。`delete-points` 用的 `table.getSelected()` 与画布已分叉。

### P1-5 系列重命名在 Electron 里**永远无法成功**
`src/js/app.js:416-424`

两个独立故障：(a) Electron 不支持 `window.prompt`，处理器抛 `Error: prompt() is not supported.` 后静默放弃；(b) `dblclick` 被派发给了首次点击就已卸载的节点（标签每次 `series` emit 都同步重建）。

### P1-6 打开图片对话框提供 TIFF，但 Chromium 无法解码 → 静默无反应
`electron/main.js:66,76` + `src/index.html:124`

主进程按扩展名生成 `data:image/tif;base64,…`，Chromium 无 TIFF 解码器 → `new Image()` 触发 `onerror` → Promise 拒绝，**`openImage()` 没有 catch，不弹任何提示**。

**我的独立复核**（Electron 渲染进程，PIL 生成的合法 TIFF）：`image/tiff → DECODE FAILED`；PNG/WebP 正常。审查代理另用 .NET `System.Drawing` 交叉验证了 TIFF 本身合法。

**这直接推翻了 README 的"支持 TIFF"。**

### P1-7 活动系列为空时导出被拒，哪怕别的系列有数据
`src/js/app.js:741-756`（用 `s.series[s.activeSeries]` 判定） vs `src/js/state.js:240-256`（`exportPayload` 含全部系列）

用户看到"暂无数据点"提示，什么都没导出。

## P2 · 安全与健壮

### P2-1 未校验的任意文件读取（`file:readText` 是完全没被使用的特权通道）
`electron/main.js:81-96`、`electron/preload.js:8-9`

渲染进程无 `nodeIntegration`、无 `fs`，却能通过 `window.gd.readText(<任意路径>)` 读到主进程能读的任何文件。**实测读到 `C:/Windows/win.ini` 和用户 `.gitconfig`**，打包版同样成立。`fs.readFileSync(12345)` 被当作文件描述符处理 → `EBADF`，证明零输入校验。

`file:readText` 在 `src/` 里**没有任何调用者**——纯多余特权。`file:readBinary` 只被 `app.js:844` 调用一次，路径取自用户打开的 `.gdw` 文件里的字段，**任何工作区文件都能把它指向任意路径**。

**修复**：删掉 `readText`；`readBinary` 限定在用户已批准的根目录内。

### P2-2 CSP 无法约束本地文件 —— `file://` 下 `'self'` 匹配任意本地文件
`src/index.html:5-6`

`script-src 'self'` 在 `file://` 文档里等于"任意 file: URL"。**实测（页面上下文，非 DevTools）**：`file://` 脚本 **LOADED** 并执行成功；`fetch('file:///C:/Windows/win.ini')` **ALLOWED**；而远程脚本/远程 fetch 被正确拦截。

渲染层存在 `innerHTML` 汇（`app.js:404` 的 `line.color` 未转义、`table.js:89`），与 P2-1 组合后构成链。

**修复**：用自定义 `app://` 协议承载渲染进程，并显式加 `connect-src 'none'` `object-src 'none'` `base-uri 'none'`。

### P2-3 原生菜单 `Delete` 快捷键绕过输入框保护
`electron/main.js:175`

在标定数值输入框里按 Delete 想删字符，菜单加速键**无条件**触发 `delete-points`，删掉选中的数据点。渲染层自己做了这个保护（`app.js:1195-1198` 在 INPUT 内提前返回），但 Windows 上菜单加速键先于页面拿到按键。

### P2-4 `pointercancel` 被当成完成的点击/拖拽
`src/js/ui/canvas.js:419-420`（`endPointer` 同时绑定 pointerup 与 pointercancel）

手势被系统接管时会**凭空造出一个数据点或标定点**。

### P2-5 90ms 去抖的掩膜重建未在追踪前 flush
`src/js/app.js:300-323`、`:617-623`（`runTrace` 只在 `maskInfo === null` 时重建）

改完采样参数后 90ms 内点「自动追踪」→ **追踪用的是旧掩膜**。实测：掩膜 5194 px → 改参数后 470865 px，立即追踪得 162 点，等去抖后追踪得 6 点。

## 我自己实测的「没有问题」项

这些我本来怀疑过，测完确认没问题：

- **跨层一致性**：i18n 中英词典各 161 键完全对齐；72 个 `data-i18n` 绑定全部有对应键；51 个 `getElementById` 目标全部存在；CSS 变量全部有定义；8 个 IPC invoke / 3 个 send 与主进程完全对应；19 个原生菜单动作全部有处理分支。
- **性能不是瓶颈**（原本担心大扫描件会卡）：2480×3508（870万像素）下，掩膜构建 **119ms**、掩膜叠加层 **25ms / 33MB**、追踪 **1ms**。Electron 侧 `render()` 在 2 万个点时 6.4ms。
- **虚拟化表格没有漂移**：`ROW_HEIGHT = 22` 与实测渲染行高一致；226 个滚动位置扫描**零个空洞像素**。
- **工作区往返健全**：标定、系列、采样参数、区域全部无损还原，还原后的标定映射与原值逐位一致。
- **坐标数学精确**：`imageToScreen`/`screenToImage` 互逆误差 0；缩放锚点漂移 ≤ 6.4e-13 px；缩放钳位 [0.02, 40] 正确。
- **导出器边界不崩**：空系列、单点、退化范围全部安全，无除零。
- **打包产物健全**：asar 内含全部文件，`main.js` 与源码 SHA-256 一致，preload 13 个方法全在，图标可从 asar 内读取。
- **CSP 在源级有效**：eval / new Function / 内联脚本 / 远程脚本 / 远程 fetch 全部被拦截。
