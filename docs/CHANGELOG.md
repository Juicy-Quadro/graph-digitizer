## v1.5.0

**界面简化，少走步骤**

- **检查器分成三个页签**：`曲线` / `云图提取` / `导出`。以前六个面板从上到下堆在一起，要用云图或导出就得滚过所有用不上的面板
- **面板跟着当前工具走**：选了「自动追踪」就显示自动追踪的设置，并且排在最上面；「区域采样」同理。用哪套参数，调哪套参数
- **打开图就自动识别曲线色与背景色**：以前要拿 `L` 和 `B` 各点一次才能追踪，现在打开图就自动猜好，识别结果直接画成半透明掩膜叠在图上——猜得对不对，一眼就能看见。不对就用 `L` / `B` 重新采样
- **AI 读完刻度就自动提取数值场**：以前读完刻度还要再点一次「提取数值场」
- **数据抽屉右上角多了「导出 / 复制」**：数据就在眼前，不用滚到最下面的导出面板

**刻度位置只做一点点校正**

缩放的换算修好之后，模型报的位置已经很准了：直线色标上，数字的直线残差中位数只有 0.039%。而程序找到的印刷标签位置**换上以后反而更差**（37 张里 25 张变差、只有 2 张变好）——旁边可能有根本不是数字的文字块，取它的中点就把数字挪了地方。

所以程序的位置**只在离模型给的位置很近时（色标长度的 0.2%）**才用，也就是只够扶正一下。最差的那张图，残差从 2.05% 降到 0.21%。

**文档**

- README 改成只讲当前版本：功能怎么用、怎么用好、更新历史移到本文件

## v1.4.2

benchmark 又查出四个问题，都已修。

- **裁剪图放大过，模型报的位置没除回去**：裁剪图在送给模型前会放大到长边 1400 像素，模型是在**放大后的图**上读位置的，应用却当成原图坐标。差多少？放大 4.7 倍就差 4.7 倍。修完实测**位置偏差中位数从 84.9 像素降到 1.5 像素**
- **程序找刻度标签时把旁边的图例当成了刻度**：旧办法是「取离色标最近的那一列文字」，旁边只要有更近的别的文字就全找错，一个孤零零的脏点就能把刻度全带偏。改成**行投影**（窗口里带文字的行一个都不丢），谁是真刻度交给后面的就近配对去定。实测最差偏差从 **129 像素降到 35 像素**
- **水平色标整个是错的**：刻度标签在上下方，代码只看左右 → 一个都找不到；更糟的是「避开边框」的 25% 收窄用在了**长度方向**上，色带从色标的 25% 处开始编号，和用户填的刻度值对不上，**数值是错的**。现在编号走满整条长度，标签在上下方找
- **benchmark 自己量错了**：`residualPrinted` 用的是参考实现找到的标签位置，而参考实现的窗口起点在色标右侧 20 像素——真实图上刻度就贴在色标边上，它**根本没看见真刻度**，量的是坐标轴数字。那个「28.98%」是在测参考实现的毛病。改成用**应用自己的**标签代码

另外，刻度位置现在只在**离模型给的位置很近（色标长度的 1%）**时才采用：模型读位置其实很准，而旁边可能有根本不是数字的文字块，取它的中间会把数字放错地方。真实图实测：程序位置上的数字残差从 **2.85% 降到 0.05%**。

评测工具本身也修了两个：**「中断续跑」其实从来没生效**（已测过的集合建了没用），以及后台跑时管道一断就 **EPIPE 弹窗**（`console.log` 的 `%d` 在新版 node 里也要改写法）。

回归套件扩到八套、201 项断言（algorithm 101 / llm 34 / cross-layer / theme 7 / experience 6 / smoke 11 / ui 18 / papers 20）。

## v1.4.0

新增了一套**几百张真实论文图**上的能力评测（见 [`BENCHMARK.md`](BENCHMARK.md)），它当场查出了三个问题，都已修：

- **模型读不出真实图上的刻度标签**：裁剪窗口把数字切掉了，而且色标是 1:8 的细条，缩放后标签只剩几像素高。现在窗口**跟着文字走到头**，裁剪图**放大到长边 1400 像素**。修完后模型能读出 `-2.950`、`-3.694` 这样的真实刻度
- **模型读数字很准，但报位置不准**：数字的直线残差只有 **0.01%–0.11%**，位置却偏 24–63 像素。于是改成**程序找位置、模型只给数字**——刻度文字的暗色块由程序精确找到，两边按顺序就近配对
- **经典追踪器在真实论文图上基本失效**：400 张图里只追出 1 条曲线（坐标轴、网格、文字全进了掩膜）。这正是模型能补上的地方

评测框架本身也进仓库了（`tools/bench_fetch.py`、`tools/bench-reference.js`、`tools/bench-llm.js`、`tools/bench-report.js`），图随时可以重建：

```bash
python tools/bench_fetch.py --count 400 --papers 140
electron tools/bench-reference.js
electron tools/bench-llm.js --task bar
node tools/bench-report.js
```

另外修掉一个会让「AI 读取刻度」直接报错的问题：裁剪窗口的变量名遮蔽了全局 `window`。

回归套件扩到八套、193 项断言。

## v1.3.1

**真实论文图回归修的两个真 bug**

回归不再只用合成图，而是从 **arXiv 论文源码包**里取真实图（arXiv 2601.00342），裁出四个带色标的面板（jet 色标、发散色标、标签只标中段、全负值区间）做回归。色标矩形和刻度标签位置由**程序测量**，真值不靠手抄像素坐标。

- **颜色查找表太粗**：原来用 32×32×32 固定查找表，一格 8 个色阶——而 1800 像素长的色标上 8 个色阶相当于 **57 像素**，颜色认错了带，数值偏 **2%**。改成精确最近邻搜索后降到 **0.8%**
- **锚点外的值被压平**：真实论文里标签常常只标中间几段，原实现把锚点之外的值压平成端点值，等于把一段云图全报成同一个数。改成沿最近两个锚点的直线外推

实测颜色读数误差 **0.73%–1.72%（量程百分比）**，覆盖 jet 与发散色标、标签只标中段等真实情况。回归套件扩到八套、179 项断言。

## v1.3.0

**新增：云图提取（Cloud Map）**

- **按色标还原云图数值**：框选色标 → 给刻度值 → 提取出整幅图的数值场。颜色不再是颜色，而是数字
- **刻度值两种来源**：AI 自动读（MiniMax-M3 视觉模型读刻度标签上的数字和位置）或手动填，两种可以混用，模型读不准的直接改
- **三种导出**：网格 CSV（宽表，Excel/Origin 直接画等值线）、点表 CSV（X, Y, 数值）、数值场 PNG
- **坐标标定与色标标定互相独立**：网格的 X/Y 可以用标定后的逻辑坐标，数值用色标
- **API key 只存在主进程**：`safeStorage` 加密，界面层拿不到也读不回

**新增：AI 提取曲线**

- `Curve Detection` 面板里多了一个 `Extract curves with AI`：模型读出图里的曲线，作为新系列直接进数据表，走的是同一条 AI 通道、同一个密钥

说明见 [`CLOUD-MAP.md`](CLOUD-MAP.md)。

## v1.2.0

一次独立审计发现 **36 项缺陷**，本版本全部修完。最关键的几条：

- **标定模型修正**：原实现把「垂直投影」和「仿射等值线」两套不兼容的几何混着用，两轴不垂直时逻辑坐标会错乱。已统一为仿射基分解，在真实倾斜样例上曲率降低 **58 倍**，真值点 X 单调性从 77/108 恢复到 **108/108**
- **改标定后所有点自动重算**（此前点数组逐字节不变，界面看着刷新了、数字却是旧的）
- **打开新图自动清空**上一张图的标定与数据
- **渲染进程迁到自定义 `app://` 协议**，`script-src 'self'` 才真正管得住本地文件；同时删掉了没有任何调用者的 `readText` 特权通道，文件读取限定在用户打开过的目录内
- **点击/拖拽判定改用屏幕像素**：此前按图像像素算，放大 40 倍后拖 40 像素会被当成点击，缩小后抖 2 像素反而丢掉点击
- **画布与表格的选中态统一**：删掉一个点后，画布不再把「选中」色画到隔壁点上
- **原生菜单移除 `Delete` 加速键**：在标定输入框里按 Delete 想删字符，不再顺手删掉数据点
- **八种导出格式统一处理缺失测量**：不再出现 `NaN` 坐标或被伪造成 0 的数字

完整台账见 [`AUDIT-2026-10-25.md`](AUDIT-2026-10-25.md) 的「修复台账」一节。
